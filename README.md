# Koitechs · Catalog → Linear

Приклад окремого проєкту для Codex: завантажуємо сьомий документ PDD, отримуємо перевірений набір постановок для Linear. Без сайту та без окремого AI API: аналітичну роботу виконує Codex через скіли й агентів.

**Перший раз користуєшся GitHub? Почни з [простих кроків у START_HERE.md](START_HERE.md).**

## Як почати

Відкрий цю папку як проєкт у Codex і напиши:

> Використай $catalog-to-linear. Опрацюй input/07_GRANDAR_Каталог_технічних_задач.docx. Підготуй draft для Linear, залучи окремого рев’юера. Покажи проблеми та приклади задач. Нічого не публікуй.

Готовий локальний приклад уже лежить у `output/grandar-demo/preview.md`. Це результат структурного перенесення; він ще потребує змістовного рев’ю. `issues.json` — локальний формат обміну, не готовий payload API Linear і не універсальний CSV importer.

Для іншого клієнта поклади його каталог у `input/` і вкажи файл у запиті. GRANDAR — тільки приклад; його факти не можна переносити до іншого клієнта.

## Що де лежить

| Папка | Призначення |
| --- | --- |
| `.agents/skills/` | Чотири скіли: повний прогін, читання, рев’ю, передача в Linear |
| `roles/` | Межі відповідальності виконавців |
| `agents/` | Інструкції для делегування агентам; це prompt-файли, не автоматично зареєстровані custom agents |
| `input/` | Незмінений вхідний DOCX |
| `scripts/` | Відтворюваний DOCX → JSON + Markdown, без мережевих запитів |
| `output/` | Чернетки, перевірки, згодом журнал синхронізації |
| `docs/` | Контракт Linear і походження прикладу |

Координатор → аналітик → технічний рев’юер → підготовка Linear. Аналітик зберігає зміст, рев’юер перевіряє його незалежно, координатор приймає результат. За відсутності multi-agent tools ті самі інструкції виконуються послідовно; такий review не називається незалежним.

## Локальний прогін

Потрібен Python 3.10+, сторонніх пакетів немає:

```bash
python3 scripts/catalog.py input/07_GRANDAR_Каталог_технічних_задач.docx --out output/grandar-new-run --project-key grandar-demo
python3 -m unittest discover -s tests
```

Кожен прогін пише в нову output-папку; існуючі результати не перезаписуються.

Парсер підтримує фактичний формат GRANDAR від 08.09.2026. Для іншого layout скіл читає джерело й адаптує нормалізацію; скрипт не вгадує відсутні поля. Невідомі поля або неповні блоки зупиняють експорт. Зображення, коментарі й tracked changes не інтерпретуються як звичайний текст.
