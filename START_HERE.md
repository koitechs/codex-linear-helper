# Як користуватися — без знання Git

Це папка з інструкціями для Codex. Ти даєш сьомий документ PDD — каталог технічних задач — і Codex готує задачі для робочої борди. Програмувати, робити commit або push для щоденної роботи не потрібно.

## Перший запуск

1. Відкрий [koitechs/codex-linear-helper](https://github.com/koitechs/codex-linear-helper). Репозиторій публічний: для перегляду та скачування не потрібні GitHub-акаунт, запрошення чи членство в Management. Для подальшої роботи потрібен власний доступ до Codex.
2. Натисни **Code → Download ZIP**. Розпакуй архів повністю у зручну папку. Не відкривай тільки один файл і не працюй всередині ZIP. [Інструкція GitHub](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives).
3. Відкрий застосунок Codex, увійди у свій акаунт із доступом до Codex та додай розпаковану папку як локальний проєкт. Обирай папку, де одночасно лежать `AGENTS.md`, `START_HERE.md`, `input` і `scripts`. Прихована папка `.agents` теж має залишатися на місці. [Локальні проєкти Codex](https://learn.chatgpt.com/docs/projects).
4. Створи задачу в цьому проєкті та встав текст нижче. Дочекайся результату й відповідай на конкретні запитання Codex, якщо вони виникнуть.

Пробний запит — готовий документ уже всередині:

```text
Прочитай AGENTS.md і використай $catalog-to-linear.
Опрацюй input/07_GRANDAR_Каталог_технічних_задач.docx як демо GRANDAR.
Project key: grandar-demo. Створи нову папку результату, не перезаписуй попередню.
Підготуй задачі для Linear, проведи перевірки й залучи окремого рев’юера,
якщо агенти доступні. Покажи мені результат і питання до документа.
Нічого не публікуй у Linear.
```

Якщо `$catalog-to-linear` не знаходиться, напиши: «Прочитай `.agents/skills/catalog-to-linear/SKILL.md` у цій папці й виконай його». Не треба встановлювати скіли глобально чи переносити окремі файли.

Для локальної обробки потрібен Python 3.10 або новіший. Codex сам перевіряє доступний runtime і запускає скрипт; якщо Python відсутній, він пояснить конкретну дію для встановлення. Окремий OpenRouter або OpenAI API key для цього хелпера не потрібен; сама робота Codex використовує твій доступ до Codex.

## Свій клієнт

Скопіюй каталог `07_...docx` у папку `input` через Finder/Провідник. Демо можна залишити; у запиті вкажи точну назву свого файла:

```text
Використай $catalog-to-linear для input/07_МІЙ_КЛІЄНТ.docx.
Це проєкт «Назва проєкту», project key: my-client-portal.
Підготуй локальну чернетку задач для Linear, перевір повноту,
збережи ID, labels, оцінки й залежності. Покажи результат і проблеми.
У Linear поки нічого не створюй.
```

Заміни назву файла, назву проєкту та `my-client-portal`. Project key — коротка стала назва латиницею без пробілів: своя для кожного проєкту, однакова для наступних версій його документа. Codex може допомогти її підібрати.

Вбудований парсер перевірено на форматі GRANDAR від 08.09.2026. Якщо оформлення іншого каталогу відрізняється, Codex має перевірити та адаптувати читання; він не повинен мовчки пропускати задачі.

## Де результат

Codex дасть посилання на файли у новій папці `output`:

- `preview.md` — усі постановки для читання.
- `issues.json` — дані для подальшої передачі.
- `checks.json` — автоматичні перевірки.
- Review-файл — змістовні проблеми та питання; його готує агент після автоматичних перевірок.

Позначка `Requires Tech Lead validation` означає, що технічне рішення ще треба підтвердити. Успішна обробка файла не означає, що всі задачі вже готові до розробки.

## Коли захочеш перенести у Linear

Після перегляду результату напиши:

```text
Перенеси перевірений пакет з output/НАЗВА_ПАПКИ в Linear:
workspace — НАЗВА, team — НАЗВА, project — НАЗВА.
Створи їх як backlog drafts, збережи Task ID і перевір дублікати.
Задачі з невирішеними blockers не публікуй. Дай посилання на створені задачі.
```

Для цього у твоєму Codex має бути доступне підключення до потрібного Linear workspace з правами створювати задачі. Доступ до GitHub не дає доступу до Linear. Якщо підключення відсутнє, Codex повідомить про це, а локальні результати залишаться доступними. Живе перенесення у Linear не входило до тесту цієї версії.

## Як оновлювати

Повторно скачай ZIP і розпакуй у **нову** папку. Свої вхідні документи та попередні результати збережи зі старої папки, потім відкрий нову папку в Codex. Для того самого проєкту використовуй попередній project key. Якщо вже публікував задачі, збережи також `sync-state.json` із попереднього результату та дай його Codex для звірки. Не копіюй старі `scripts`, `.agents` чи `AGENTS.md` поверх нової версії.
